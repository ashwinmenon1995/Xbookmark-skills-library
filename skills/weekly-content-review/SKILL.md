# Weekly content review

Look at how the user's posts did. Append what worked to their private `what-works-for-me.md`. Do not write those learnings anywhere else.

## Limits

- Do not post, send, pay, sign up, or delete unless the user explicitly tells you to do that specific thing.
- Do not reply to comments, boost a post, or change a live post.
- Performance numbers come from a connector the user authorizes, or from numbers the user pastes. Do not scrape, and do not invent numbers.
- Append learnings only to the user's private `what-works-for-me.md`. Never append them to this repo, to a shared file, or to a public library.

## Steps

1. Get this week's results. Use a connector the user has authorized, or ask them to paste the numbers (platform, post, and the results they care about). If you have neither, ask and stop.
2. On the first run, copy `templates/what-works-for-me.template.md` to `what-works-for-me.md` in the private folder. Confirm that folder is not this repo.
3. Compare the results with `my-skills.md` and with the content plan for this week, if there is one. Note which entry ids the posts used.
4. Append one learning per pattern that the numbers support. Do not rewrite older learnings. To correct one, append a new learning that names it.
5. Each learning records the date, the platform, the post label or URL the user supplied, the numbers they supplied, what worked, the library entry ids, and what to do next time.
6. Show the new learnings to the user. Do not copy `what-works-for-me.md` into this repo or into any shared file.
